# 実装用プロダクト仕様

## プロダクトゴール

週1回だけ献立を考え、平日は5つの献立から選んで作る。機能追加の判断基準は「仕事後に考える量が減るか」である。

## 対象とスコープ

- 固定された2ユーザーが1つのCoupleSpaceを共有する非公開アプリ
- iPhoneのホーム画面から使うPWA
- 週5献立＋余裕日2日。曜日には固定しない
- 初期版のレシピ取り込みはInstagram URLと一般Web URL。TikTok・画像OCRは対象外

## 中核フロー

### 週間計画

1. 保存済み主菜からプログラムが10候補を生成する。
2. 1枚ずつ右（採用）/ 左（スキップ）へ送り、直前の操作は戻せる。
3. 5主菜を確認して確定する。
4. 各主菜へ副菜1品・汁物1品を自動設定する。一品料理では省略可。
5. 全献立の材料をIngredient単位で合算し、互換単位の在庫を差し引く。
6. 「家にあるものチェック」で差異を補正し、任意で保険食材1〜3品を追加する。
7. 買い物リストを確定する。

### 平日

1. 未調理の週間献立を、傷みやすい在庫を使う順に見る。
2. 献立セットで主菜・副菜・汁物、各自のご飯量、カロリー/PFCを確認する。
3. 必要なら副菜または汁物だけ差し替える。
4. 「作った」を1回実行すると、在庫減算・食事履歴・調理履歴を同じ処理で保存する。
5. そのレシピの初回調理時だけ3段階評価を求める。

## 機能要件

- レシピ：2列グリッド、詳細、検索、指定フィルター、ソート、評価、お気に入り、1〜4人分換算、1手順ずつの調理モード
- 推薦：AI不使用。評価、栄養、在庫、履歴、コスト、特殊調味料、ジャンルをスコア化する
- 在庫：購入済みで加算、作ったで減算、家にあるチェックで補正。購入日と保存目安から`そろそろ使いたい`を算出する
- 買い物：カテゴリ順をユーザー設定できる。購入済み項目は消さず薄く表示する
- 記録：食事履歴、週平均夕食カロリー、本人だけが見られる体重と推移
- 同期：共有データをSupabase Realtimeで2人へ反映する
- バックアップ：1日1回、Vercel Blobへ出力し30日保持する。復元手順も管理する

## 対象外

- 公開登録、3人以上のグループ、課金、App Store公開
- 献立の曜日固定、賞味期限の都度入力、iPhone通知
- 毎週Webから自動取得する新規レシピ
- 推薦時のAI呼び出し、失敗時の上位AIモデル自動再試行
- 主菜・副菜・汁物の調理手順の自動並列最適化

## 合理的仮定

1. 週の境界はAsia/Tokyoの月曜00:00〜日曜23:59とし、曜日割当は持たない。
2. ユーザー選択＋個人PINで認証する。PINはユーザー選択だけでは本人確認にならないため、サーバー側で検証し、平文保存せず、連続失敗を制限する。Supabase Auth sessionの安全な発行方法はDevelopment環境で先に検証する。
3. 共有レシピへの評価はユーザーごと、お気に入りもユーザーごとに保持する。「もう作らない」は通常推薦から除外し、2人のどちらかが付けた場合の扱いは推薦仕様で固定する。
4. 在庫はCoupleSpace共有。体重は完全な個人データ。ご飯量は個人設定だが献立画面では相手の設定量も表示できる。
5. 料理画像は取得権限と利用条件を満たす場合だけ複製し、取得不能時はプレースホルダーを使う。
6. 単位換算不能な材料は別明細として残し、誤った合算・減算をしない。
7. バックアップはDBの論理データとStorage参照情報を対象とする。画像バイナリの二重保存要否はバックアップPhaseで容量と復元要件を確認する。

## 受け入れ基準

2人が開発環境で1週間の流れを通し、レシピ保存から週間決定、買い物、調理、在庫更新、栄養表示、履歴、個人体重、同期、バックアップ復元確認まで完了できること。
