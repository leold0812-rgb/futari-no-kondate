# 週間推薦仕様 v0

AIを使わない、説明可能でテスト可能なスコアリングとする。係数は運用データを見て変更できるようalgorithm versionを保存する。

## 対象集合

保存済みの`主菜`だけを対象にする。URLだけ保存・解析未確認・材料不足など利用不能状態は除外する。どちらかのユーザーが`もう作らない`にした料理は通常候補から除外し、詳細画面からの手動追加は許可する。

## 基本スコア案（1人前）

| 要素 | 点 |
|---|---:|
| また作りたい（ユーザーごと、最大2人） | +14 / 人 |
| お気に入り（最大2人） | +6 / 人 |
| 未調理 | +8 |
| 高タンパク基準を満たす | +12 |
| 低カロリー基準を満たす | +10 |
| 在庫で主要材料を多く賄える | 0〜+10 |
| 今週の他候補と食材を使い回せる | 0〜+8 |
| 30日以内に作った | -10〜0（経過日で減衰） |
| 高コスト | -8 |
| 特殊調味料が必要 | -4 |

栄養基準値は食品マスタ導入時に実データ分布を確認して固定する。それまではタグを根拠にし、数値を捏造しない。

## 10候補の選択

1. 全対象を基本スコア降順にする。同点は未調理、最終調理が古い、追加が新しい、IDの順で決定的に並べる。
2. 未調理を原則2品、対象が十分で多様性を損なわなければ3品確保する。
3. 高コストは原則1品まで。候補不足時のみ2品目を許可し理由をbreakdownへ残す。
4. 同一の大分類（肉/魚/麺/ごはんもの等）が過半数にならないよう、次点と差し替える。候補数不足時は緩和する。
5. 残枠をスコア順で埋める。常に選定理由のbreakdownを保存する。

## 副菜・汁物

主菜5品確定後、候補セット全体を見て次の重みで選ぶ。

- 食材使い回し +15
- 現在庫の消費 +12
- そろそろ使いたい食材 +14
- 主菜で不足する栄養カテゴリの補完 +8
- 低カロリー +6
- 最近の重複 -6

同じ副菜・汁物の週内重複は原則避ける。一品料理は両方またはいずれかを省略できる。食材の合算結果が不自然に増える場合は全体スコアで組み合わせを再評価する。

## 余裕日

在庫・古い食材・保険食材で作れる割合を最優先し、15〜20分、追加購入0〜2品を優先する。ここでもAIは呼ばない。

## 必須テスト

- もう作らない料理が自動候補に入らず手動追加はできる
- 未調理が可能なら2〜3品、高コストは原則1品
- 最近作った料理とジャンル偏りが補正される
- 同じ入力とalgorithm versionから同じ10件が返る
- 候補不足時にも重複・例外で失敗せず、緩和理由が残る
