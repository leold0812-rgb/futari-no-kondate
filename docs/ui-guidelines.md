# UIガイドライン

## 方向性

おしゃれなカフェ・レシピアプリの落ち着きと、買い物中・調理中でも迷わない実用性を両立する。かわいさは控えめにする。

## デザイントークン案

- 背景：Ivory `#F7F3EA`
- 面：Warm White `#FFFDF8`
- 文字：Charcoal `#2F312E`
- 主色：Muted Green `#75866A`
- 主色濃：`#53634B`
- 注意：Terracotta `#B56F52`
- 境界：`#DED8CC`
- 角丸：カード16px、入力12px、pill 999px
- 影は弱く、階層は余白と面色を優先する

実装時はCSS変数へ集約し、コントラストを検証する。

## レイアウト

- iPhone幅を基準にし、本文最大幅は640px程度
- 下部5タブ：ホーム / レシピ / 在庫 / 買い物 / 記録
- bottom navigationはSafe Areaを含め、本文が隠れない余白を確保
- タップ領域は最低44×44px、主要ボタンは片手で届く下側へ置く
- 情報はカードに分けるが、過剰な装飾や入れ子カードを避ける

## 主要画面

- ホーム未決定：`今週の献立を決める`を最優先の1アクションとして表示
- ホーム決定後：5献立を横スクロール。調理済みは薄くし、`そろそろ使いたい`食材の料理を前へ
- スワイプ：カードは1枚。右=`作る`、左=`スキップ`を色だけでなく文字とアイコンでも示す。ボタン操作も併設し、`1つ戻る`を常設
- レシピ一覧：2列。画像、料理名、時間、主要タグを表示し情報を詰めすぎない
- 買い物：カテゴリ見出し＋食材名＋数量。購入済みを残し、チェックと低いopacityで表現
- 調理：1ステップを大きく表示。画面スリープ対策は後続検討とし、初期実装を複雑にしない

## 状態と文言

- loading、empty、error、offline、権限エラーを各画面で設計する
- エラーは「何が起きたか」「データが保存されたか」「次に何をすればよいか」を日本語で示す
- URL解析失敗時は失敗扱いで行き止まりにせず、`URLだけ保存`と`手入力で続ける`を示す
- 破壊的操作は確認し、二重送信中はボタンを無効化する

## アクセシビリティ

- 色だけで状態を伝えない
- 入力には常時表示labelを付ける
- スワイプ操作だけに依存しない
- Dynamic Type相当の文字拡大でも主要操作が欠けないようにする
- `prefers-reduced-motion`ではカードアニメーションを抑える
